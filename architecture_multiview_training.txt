MULTI-VIEW PANOPTIC SEGMENTATION WITH QUERY PROPAGATION
Architecture & Pipeline Documentation (Updated: February 2026)
═══════════════════════════════════════════════════════════════════════════


OVERVIEW
────────
This system implements multi-view panoptic segmentation on ScanNet++ using:

  1. MapAnything backbone (FROZEN)    – DINOv2 ViT-L + cross-view transformer
  2. Panoptic DPT head (TRAINABLE)    – FPN-style multi-scale feature extraction
  3. Mask2Former decoder (TRAINABLE)  – Query Propagation for cross-view consistency

Key Design Principle:
  Query propagation ensures that Query #K represents the SAME physical entity
  across all views — consistency is STRUCTURAL (same queries), not regularised
  by an explicit cross-view loss.

Current Status (v2 — January 2026):
  • Warped attention masks: DISABLED (INPUT.LOAD_DEPTH = False)
  • Alpha blending: DISABLED (initial_attn_mask = None for all target views)
  • Only QUERY PROPAGATION is active between reference and target views
  • Code for geometric warping remains in the codebase for future experiments

Files:
  m2f_train_multiview.py              – Training script (~3951 lines)
  scannetpp_panoptic_dataset_mapper.py – Dataset mapper (~1634 lines)
  m2f_inference.py                    – Multi-view inference + 3D point cloud
  m2f_evaluate.py                     – Per-scene evaluation on validation set
  register_datasets.py                – Detectron2 dataset registration

─────────────────────────────────

  ├── data/<scene_id>/

  │   └── scans/
  │       └── mesh_aligned_0.05.ply               # 3D mesh (for depth rendering)
  │
  ├── panoptic/                                   # Training GT annotations
  │   └── <scene_id>/
  │       ├── <stem>.png                          # Panoptic map (RGB-encoded)
  │       └── <stem>.json                         # Per-image segments_info
  │
  └── panoptic_val/                               # Validation GT annotations
      └── <scene_id>/                             # 48 scenes (same format)

  Per Training Sample (N views from one scene):
    • images:           [N, 3, H, W]   – RGB (undistorted pinhole)
    • camera_poses:     [N, 4, 4]      – Camera-to-world (OpenCV convention)
    • camera_intrinsics:[N, 3, 3]      – 3x3 intrinsic matrix K
    • panoptic_targets: [N, H, W]      – Panoptic ID = semantic_id × 10000 + instance_id
    • depth (optional): [N, 1, H, W]   – Pre-rendered from mesh (DISABLED in current config)


1.2  Dataset Mapper: ScanNetPPMultiViewDatasetMapper
─────────────────────────────────────────────────────
  File: mask2former/data/dataset_mappers/scannetpp_panoptic_dataset_mapper.py

  Purpose:
    Loads N views per scene with consistent camera geometry and panoptic GT.
    All views are resized to the same dimensions to enable batched processing.

  Key Components:

  a) Camera Pose Loading
     - Primary: NerfStudio transforms_undistorted.json (c2w, OpenGL → OpenCV)
     - Fallback: COLMAP cameras.txt + images.txt (w2c → c2w conversion)
     - Conversion: OpenGL (+Y up, -Z forward) → OpenCV (+Y down, +Z forward)
       via flip matrix: diag([1, -1, -1, 1])

  b) View Selection (Overlap-Aware)
     - Algorithm: select_diverse_views() — greedy scoring from random reference
     - Objective: HIGH overlap (50-70%) between views for meaningful query propagation
     - Score = 0.6 × direction_similarity + 0.4 × distance_score
     - Constraints:
       MIN_CAMERA_DISTANCE = 0.3m   (avoid near-duplicates)
       MAX_CAMERA_DISTANCE = 5.0m   (avoid zero-overlap pairs)
       MAX_OVERLAP = 0.8            (prevent identical views)
     - Small random jitter added for diversity across training epochs

  c) Consistent Resizing (Two-Pass)
     Problem: Different views may have slightly different aspect ratios after resize.
     Solution:
       Pass 1 — Resize all N views independently
       Pass 2 — Find max(H), max(W) across all views, pad to common size
       Size divisibility enforced to 32 (Mask2Former requirement)
     Training: Random short edge from (384, 416, 448, 480), max_size=640
     Eval:     Fixed short edge = 480, max_size = 640

  d) GT Instance Capping
     Problem: Scenes with 95+ GT segments leave only 5 "no-object" queries out of 100,
     causing extreme CE gradients → NaN in AMP fp16.
     Fix: MAX_GT_INSTANCES = 80, keep largest by area. Ensures ≥20 queries for no-object.

  e) Panoptic ID Encoding
     panoptic_id = semantic_id × 10000 + instance_id
     CRITICAL: PNGs saved via cv2.imwrite(path, rgb[:,:,::-1]) swap R↔B channels.
     Decoding: id = B + G×256 + R×65536 (NOT standard R + G×256 + B×65536)

  f) Depth Loading (Optional, DISABLED)
     - Pre-rendered depth  (uint16 PNG, millimetres → metres)
     - Searched in: <scene>/dslr/render_depth/<stem>.png
     - Used for warped attention masks (DISABLED: INPUT.LOAD_DEPTH = False)

  g) Filtered Dataset Wrapper
     FilteredDataset wraps MapDataset to handle None returns (scenes without camera data).
     Retries with next index up to 50 times. Defined at module level for pickling with
     'spawn' multiprocessing start method.

  h) Custom Collation: multi_view_collate_fn()
     Input:  List[Dict] with 'scene_id' and 'views' list
     Output: Batched tensors [B, N, ...] padded to max dimensions across batch


1.3  Panoptic Label Generation Pipeline
────────────────────────────────────────
  Tool: semantics_2d.py (ScanNet++ toolkit) → convert_to_panoptic_format.py

  Step 1: Rasterise 3D mesh annotations to 2D
    - Uses Open3D RaycastingScene with the aligned 3D mesh
    - Produces per-image: obj_ids/<stem>.pth (instance), semantics/<stem>.png (semantic)

  Step 2: Convert to Detectron2 panoptic format
    - Merges instance + semantic into panoptic_id = semantic × 10000 + instance
    - Encodes as RGB PNG using id2rgb from panopticapi
    - Produces per-image: <stem>.png + <stem>.json (segments_info)

  Split Info:
    Training:   150 scenes (nvs_sem_train_subset150.txt)
    Validation:  48 scenes (nvs_sem_val_clean.txt) in panoptic_val/

2. MODEL ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════

    Input: N Views [B, N, 3, H, W] + Camera Poses [B, N, 4, 4]
        │
        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  LAYER 1: MapAnything Backbone (FROZEN)                             │
    │  Class: MapAnythingMultiViewBackbone                                │
    │                                                                     │
    │  DINOv2 ViT-L Encoder (768-dim, patch_size=14):                     │
    │    - Encodes each view independently                                │
    │    - All params forced to float32 (paranoid half→float fix)         │
    │                                                                     │
    │  Optional Geometric Encoding:                                       │
    │    - Camera poses → quaternion + translation for MapAnything        │
    │    - _encode_and_fuse_optional_geometric_inputs()                   │
    │                                                                     │
    │  Info-Sharing Transformer (1024-dim):                               │
    │    - Cross-attention between all N views                            │
    │    - Produces shared multi-view features                            │
    │    - 2 intermediate + 1 final feature output                        │
    │                                                                     │
    │  Output: Per-view tokens [B, C, H/14, W/14]                        │
    │  Autocast: DISABLED (torch.no_grad + autocast(enabled=False))       │
    └─────────────────────────────────────────────────────────────────────┘
        │
        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  LAYER 2: Panoptic DPT Head (TRAINABLE)                             │
    │  Class: PanopticDPTHead                                             │
    │                                                                     │
    │  Purpose: Convert ViT tokens → multi-scale FPN features             │
    │                                                                     │
    │  Layer Features (4 levels per view):                                │
    │    Layer 0: Encoder features  [B, 768,  H/14, W/14]                │
    │    Layer 1: Intermediate #1   [B, 1024, H/14, W/14]                │
    │    Layer 2: Intermediate #2   [B, 1024, H/14, W/14]                │
    │    Layer 3: Final features    [B, 1024, H/14, W/14]                │
    │                                                                     │
    │  DPT Processing:                                                    │
    │    Reassemble → Resize layers → Scratch (layer_rn) → RefinNets     │
    │                                                                     │
    │  Output (per view):                                                 │
    │    res2: [B,  96, H/4,  W/4 ]                                      │
    │    res3: [B, 192, H/8,  W/8 ]                                      │
    │    res4: [B, 384, H/16, W/16]                                      │
    │    res5: [B, 768, H/32, W/32]                                      │
    │                                                                     │
    │  Initialisation: Weights copied from MapAnything's geometric DPT    │
    │  Applied to: ALL N views (shared weights)                           │
    └─────────────────────────────────────────────────────────────────────┘
        │
        ▼
    ┌─────────────────────────────────────────────────────────────────────┐
    │  LAYER 3: Mask2Former Head (TRAINABLE, SHARED across views)         │
    │  Class: MaskFormerHead + QueryPropagationTransformerDecoder          │
    │                                                                     │
    │  3a. Pixel Decoder (MSDeformAttn):                                  │
    │    Input: {res2, res3, res4, res5}                                  │
    │    Deformable attention across 4 scales                             │
    │    Output: mask_features [B, 256, H/4, W/4]                        │
    │            multi_scale_features (for transformer decoder)           │
    │                                                                     │
    │  3b. Transformer Decoder (9 layers, 100 queries, dim=256):          │
    │                                                                     │
    │    ═══════ REFERENCE VIEW (randomly selected during training) ═════│
    │    ├─ Initialise: 100 learnable object queries (query_feat)         │
    │    ├─ 9 layers: cross-attn → self-attn → FFN → predict masks       │
    │    ├─ Predicted attention mask guides next cross-attention           │
    │    ├─ Output: Q_ref [100, B, 256] (refined query embeddings)        │
    │    └─ Supervision: Hungarian matching + CE + Dice + Mask BCE        │
    │                                                                     │
    │    ═══════ TARGET VIEWS (N-1 views, after warmup) ════════════════ │
    │    For each target view:                                            │
    │    ├─ Initialise: Q_ref (propagated queries from reference view)    │
    │    ├─ Warped attention mask: DISABLED (initial_attn_mask = None)    │
    │    ├─ Alpha blending: DISABLED (no geometric guidance)              │
    │    ├─ 9 layers with self-predicted attention masks (standard M2F)   │
    │    ├─ Output: target predictions with same query identity           │
    │    └─ Supervision: Same as reference (queries maintain identity)    │
    │                                                                     │
    │    Key: Query #K predicts same semantic entity across ALL views     │
    │                                                                     │
    │  3c. Prediction Heads:                                              │
    │    Class head:  query → [B, Q, num_classes + 1]                     │
    │    Mask head:   mask_embed(query) ⊙ mask_features → [B, Q, H, W]   │
    │                                                                     │
    │  NOTE ON WARPED ATTENTION (code present but DISABLED):              │
    │    When INPUT.LOAD_DEPTH = True, the decoder supports:              │
    │    - Backward warping (preferred): tgt_depth → 3D → ref frame      │
    │    - Forward splatting (fallback): ref_depth → scatter to target    │
    │    - Alpha blending: α_l × warped + (1-α_l) × predicted            │
    │      α decays linearly: 1.0 (layer 0) → 0.0 (layer 9)             │
    │    Currently disabled to simplify training and avoid depth noise.   │
    └─────────────────────────────────────────────────────────────────────┘

3. TRAINING PIPELINE
═══════════════════════════════════════════════════════════════════════════

3.1  Training Flow: MultiViewMask2Former._forward_train()
──────────────────────────────────────────────────────────

  Step 1: Backbone (ALL views processed together)
  ┌───────────────────────────────────────────────────────────────────┐
  │  backbone_out = self.backbone(images, camera_poses, intrinsics)  │
  │  all_view_features = backbone_out['all_view_features']           │
  │  # {res2: [N, B, C, H', W'], res3: ..., res4: ..., res5: ...}   │
  └───────────────────────────────────────────────────────────────────┘

  Step 2: Reference View — Full Mask2Former
  ┌───────────────────────────────────────────────────────────────────┐
  │  ref_view_idx = random(0, N)   # Random each iteration           │
  │  ref_features = all_view_features[ref_view_idx]                   │
  │                                                                   │
  │  ref_mask_features, ref_multi_scale = pixel_decoder(ref_features) │
  │  ref_outputs = transformer_decoder(                               │
  │      ref_multi_scale, ref_mask_features,                          │
  │      initial_query_feat=None,    # Learnable queries              │
  │      initial_attn_mask=None,     # Standard attention             │
  │  )                                                                │
  │  Q_ref = ref_outputs['query_embeddings']  # [100, B, 256]        │
  │  ref_losses = compute_losses(ref_outputs, ref_gt)                 │
  └───────────────────────────────────────────────────────────────────┘

  Step 3: Target Views — Query Propagation (after warmup)
  ┌───────────────────────────────────────────────────────────────────┐
  │  for v_idx in range(N):                                           │
  │      if v_idx == ref_view_idx: continue                           │
  │                                                                   │
  │      tgt_mask_feat, tgt_multi_scale = pixel_decoder(tgt_features) │
  │                                                                   │
  │      if iter >= warmup_iter:  # Query propagation enabled          │
  │          tgt_outputs = transformer_decoder(                        │
  │              tgt_multi_scale, tgt_mask_feat,                       │
  │              initial_query_feat=Q_ref,  # ← Propagated queries    │
  │              initial_attn_mask=None,    # ← No warped mask        │
  │          )                                                        │
  │      else:                                                        │
  │          tgt_outputs = transformer_decoder(                        │
  │              tgt_multi_scale, tgt_mask_feat,                       │
  │              initial_query_feat=None,    # Independent learning    │
  │              initial_attn_mask=None,                               │
  │          )                                                        │
  │                                                                   │
  │      tgt_losses = compute_losses(tgt_outputs, tgt_gt)             │
  └───────────────────────────────────────────────────────────────────┘

  Step 4: Loss Aggregation
  ┌───────────────────────────────────────────────────────────────────┐
  │  total = ref_losses × 1.0                                        │
  │        + avg(target_losses) × 0.67/N                             │
  │        + logit_regularisation_loss × 0.01                        │
  │                                                                   │
  │  Target losses are DETACHED for monitoring (loss_ce_target, etc.) │
  │  The weighted average flows through backward for gradient update. │
  └───────────────────────────────────────────────────────────────────┘


3.2  Loss Functions
────────────────────

  Per-View Losses (standard Mask2Former):
  ┌───────────────────────────────────────────────────────────────────┐
  │  loss_ce   — Cross-entropy classification (weight: 5.0)          │
  │  loss_mask — Sigmoid binary mask loss    (weight: 2.0)           │
  │  loss_dice — Dice loss for mask quality  (weight: 5.0)           │
  │                                                                   │
  │  Hungarian matching assigns queries to GT segments.               │
  │  Deep supervision: all 9 decoder layers supervised with aux loss. │
  └───────────────────────────────────────────────────────────────────┘

  Mask Logit Regularisation:
  ┌───────────────────────────────────────────────────────────────────┐
  │  excess = (|logit| - 10.0).clamp(min=0.0)                       │
  │  loss_logit_reg = 0.01 × mean(excess²)                          │
  │                                                                   │
  │  Acts as a "soft spring" pulling logits toward [-10, 10].        │
  │  Always computed (no conditional branches) for DDP safety.        │
  └───────────────────────────────────────────────────────────────────┘

  Total Loss Composition:
  ┌───────────────────────────────────────────────────────────────────┐
  │  L_total = L_ref + 0.67/N × avg(L_target) + L_logit_reg         │
  │                                                                   │
  │  NO KL divergence loss — consistency is structural, not explicit. │
  │  NO 3D consistency loss — removed for simplicity.                 │
  └───────────────────────────────────────────────────────────────────┘


3.3  Warmup Strategy
─────────────────────
  WARMUP_ITER = max(config_value, 5000)   (minimum 5000 enforced)

  Iterations 0 – 4999:
    All views use independent learnable queries.
    The backbone, DPT, pixel decoder, and transformer decoder learn
    single-view panoptic segmentation.

  Iterations 5000+:
    Query propagation enabled — reference view queries passed to targets.
    Gradients flow through both reference and target view losses.

  Rationale:
    Enabling query propagation from iteration 0 causes ~3× gradient
    magnitude from multi-view backprop, leading to gradient explosion.
    Warmup lets weights stabilise in single-view mode first.

4. NUMERICAL STABILITY FIXES (NaN Prevention)
═══════════════════════════════════════════════════════════════════════════

Seven specific fixes were developed through iterative debugging to prevent
NaN loss during multi-view training with AMP on A40/A100 GPUs:

  Fix 1: Soft Clamp Mask Logits
  ─────────────────────────────
  Problem: Hard clamp(-10, 10) kills gradients for extreme logits, creating
           a "pressure cooker" where weights diverge undetected until logits
           blow past the clamp in one step → NaN cascade.
  Solution: soft_clamp_logits() uses tanh compression outside [-10, 10].
           Linear pass-through inside, smooth asymptote at ±15 outside.
           Always provides gradient signal back toward safe range.

  Fix 2: AMP-Aware Gradient Pipeline (GradientClippingHook)
  ──────────────────────────────────────────────────────────
  Problem: Clipping SCALED gradients (multiplied by ~65536 AMP scale factor)
           to norm=1.0 made effective gradients ~1/65536, killing learning.
           Also, sanitising scaled Inf prevented grad_scaler from detecting
           overflow and adjusting its scale.
  Solution: GradientClippingHook handles the full pipeline:
    1. grad_scaler.unscale_(optimizer)  — get real gradient values
    2. Sanitise NaN (not Inf) — let scaler handle overflow
    3. Clip UNSCALED gradients to norm=1.0
    4. grad_scaler.step() skips step if Inf found → correct AMP behaviour

  Fix 3: SafeHungarianMatcher
  ────────────────────────────
  Problem: NaN in cost matrix crashes scipy.optimize.linear_sum_assignment,
           which raises RuntimeError → DDP deadlock (one rank crashes,
           others wait forever at next all_reduce).
  Solution: SafeHungarianMatcher wraps HungarianMatcher with:
    - Pre-clamp pred_logits to [-50, 50]
    - Soft clamp pred_masks (matching _compute_losses)
    - On failure: return FALLBACK sequential matching (query i → target i)
      instead of re-raising — keeps DDP ranks synchronised

  Fix 4: Extended Warmup
  ──────────────────────
  Problem: Query propagation at iter 0 multiplies gradient magnitude by ~3×
           (ref + targets), causing immediate divergence.
  Solution: self.warmup_iter = max(cfg_value, 5000)
           First 5000 iters train all views independently.

  Fix 5: Mask Logit Bias Initialisation (Anti-Collapse)
  ─────────────────────────────────────────────────────
  Problem: Default zero-bias init means mask logits start near zero. BCE loss
           on unmatched queries (80+ of 100) pushes ALL logits strongly
           negative ("predict nothing"). Dice loss can't recover because
           gradients vanish at sigmoid(-4) ≈ 0.018 → mask collapse.
  Solution:
    - mask_embed last layer: Xavier(gain=0.5) + bias=+0.0625
    - Ensures initial mask logits are slightly positive
    - Combined with Dice:Mask weight ratio 5.0:2.0 (Dice dominant)

  Fix 6: Per-Component Learning Rates
  ────────────────────────────────────
  Problem: Same LR for all components causes either DPT under-training
           (LR too low) or mask_embed divergence (LR too high).
  Solution: get_parameter_groups() creates 4 groups:
    - DPT head:       dpt_lr (1e-5)
    - Embed heads:    base_lr (5e-5) + weight_decay=0.05 (higher!)
    - SemSeg head:    base_lr (5e-5)
    - Query prop:     base_lr × 0.1 (new component, needs lower LR)

  Fix 7: DDP-Safe NaN Handling
  ────────────────────────────
  Problem: torch.zeros_like() replacements for NaN losses disconnect from
           model parameters → DDP backward all_reduce mismatch across ranks.
  Solution: torch.nan_to_num(loss, nan=0.0) preserves computation graph.
           Always compute logit_reg_loss (no conditional branch that would
           create different graphs on different DDP ranks).

5. MULTI-GPU TRAINING OPTIMISATIONS
═══════════════════════════════════════════════════════════════════════════

5.1  DDP-Safe Batch Skipping (MultiViewTrainer.run_step)
─────────────────────────────────────────────────────────
  Problem: Invalid batches (NaN inputs, empty GT) on one GPU cause crash
           while other GPUs proceed → NCCL timeout deadlock.
  Solution: Three-stage validation with DDP synchronisation:
    1. Pre-forward:  _validate_batch() checks inputs for NaN/Inf/degenerate
    2. All-reduce:   torch.distributed.all_reduce(flag, MAX) — if ANY GPU
                     flags invalid, ALL GPUs skip the batch together
    3. Post-forward: Same synchronisation for NaN/Inf in total loss
    On skip: optimizer.zero_grad(), write zero metrics, return immediately.

5.2  MapAnything float32 Enforcement
─────────────────────────────────────
  Problem: DINOv2 ViT-L loaded via torch.hub can have mixed-precision params
           (weight=float32, bias=float16) which crashes conv2d even with autocast.
  Solution: Paranoid triple-check in MapAnythingMultiViewBackbone.__init__():
    1. self.mapanything.float()
    2. Explicit encoder.model.float()
    3. Named parameter/buffer iteration — fix any remaining float16

5.3  Autocast Isolation for Frozen Backbone
────────────────────────────────────────────
  Problem: AMP autocast enabled globally causes MapAnything's internal conv2d
           to receive float16 inputs but float32 weights.
  Solution: with torch.no_grad(), torch.amp.autocast('cuda', enabled=False):
           Completely disables autocast for the frozen backbone forward pass.
           Dynamically detects target_dtype from the model's patch_embed.proj.weight.

5.4  Memory Optimisations
──────────────────────────
  - Image resolution: 384-480 × 640 (reduced from DSLR 4000×6000)
  - AMP (fp16) enabled for trainable components
  - Padding to 32-divisible (Mask2Former deformable attention requirement)
  - IMS_PER_BATCH = 4 (per-GPU in custom DataLoader, NOT divided by world_size)
  - Gradient checkpointing code present but DISABLED (20% speed cost)
  - FilteredDataset with 'spawn' multiprocessing (avoids fork+CUDA issues)

═══════════════════════════════════════════════════════════════════════════
7. INFERENCE PIPELINE
═══════════════════════════════════════════════════════════════════════════

  File: m2f_inference.py
  Class: MultiViewPanopticInference

7.1  Multi-View 2D Panoptic Segmentation
─────────────────────────────────────────
  1. Load N views from scene (overlap-aware selection)
  2. Feed all N views through MapAnything backbone (cross-view attention)
  3. View 0 = reference → full Mask2Former with learnable queries
  4. Views 1..N-1 = targets → Mask2Former with propagated queries (Q_ref)
  5. Post-process each view: overlap merging + confidence thresholding
  6. Output: N per-view panoptic maps with consistent query IDs

7.2  3D Point Cloud Segmentation (MapAnything Integration)
──────────────────────────────────────────────────────────
  1. MapAnything provides pts3d (world-frame 3D points) + confidence per view
  2. _lift_to_3d(): Uses pts3d directly (NOT depth unprojection)
  3. _voxelize_and_vote(): Fuse multi-view predictions into unified 3D cloud

  Voxel Voting Algorithm:
    - Discretise 3D space into voxels of size 0.02m (configurable)
    - For each voxel, collect all points from all views
    - Reference view points weighted by ref_view_weight (default: 1.5)
    - Points below confidence_threshold (default: 0.5) are discarded
    - Majority vote for panoptic label per voxel
    - Complexity: O(P log P) via argsort-based grouping

7.3  Visualisation Outputs
───────────────────────────
  {scene}_rgb.ply                    – Point cloud with original RGB colours
  {scene}_semantic.ply               – Point cloud with semantic class colours
  {scene}_blended.ply                – (1-α)×RGB + α×semantic overlay
  {scene}_rgb_vs_semantic.png        – Side-by-side matplotlib comparison
  {scene}_blended_views.png          – Blended overlay from 4 viewpoints
  {scene}_pred_3d.png                – Semantic point cloud with legend

  CLI Parameters:
    --voxel-size 0.02               Voxel resolution in metres
    --ref-view-weight 1.5           Extra weight for reference view votes
    --confidence-threshold 0.5      Minimum MapAnything confidence

8. EVALUATION PIPELINE
═══════════════════════════════════════════════════════════════════════════

  File: m2f_evaluate.py

8.1  Evaluation Strategy
─────────────────────────
  1. Discover all scenes in panoptic_val/ (48 validation scenes)
  2. For each scene, select N views with GT annotations
  3. Run full multi-view inference (backbone + query propagation)
  4. Compare each view's prediction against its GT
  5. Macro-average across all scenes

8.2  Metrics
─────────────

  Standard Panoptic Quality:
    PQ = SQ × RQ    (per view, then averaged)
    SQ = avg IoU of matched segments
    RQ = F1 score of segment matching
    Computed via panopticapi.evaluation.pq_compute

  Per-View Breakdown:
    per_view_pq      – PQ computed independently per view
    pq_variance       – Variance across views within a scene
    pq_std            – Standard deviation

  Cross-View Consistency (Query Propagation Performance):
    class_consistency        (target: >0.80)
      Fraction of query pairs with matching argmax class across views.
      PRIMARY metric — directly measures if query propagation preserves
      semantic identity.

    query_cosine_similarity  (target: >0.85)
      Mean cosine similarity of query embedding vectors across view pairs.
      Measures feature-space alignment of propagated queries.

    mask_iou                 (INFORMATIONAL ONLY)
      IoU of binarised query masks across views.
      Less meaningful without warped attention guidance — low values
      (0.30-0.60) are EXPECTED and NOT a failure indicator.
      Without geometric coupling, the model is free to predict different
      spatial extents in different views while maintaining semantic identity.

8.3  Post-Processing Parameters
────────────────────────────────
    --overlap-threshold 0.6     Controls instance merging (affects PQ/SQ/RQ)
    --object-mask-threshold 0.6 Controls mask binarisation (affects PQ/SQ/RQ)
    --seed 42                   Deterministic view selection

  NOTE: Post-processing thresholds affect PQ/SQ/RQ but NOT cross-view
  consistency metrics (computed from raw decoder outputs before post-processing).
